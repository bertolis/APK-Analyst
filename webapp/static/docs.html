1. What APKAnalyst is

APKAnalyst is an AI security analyst agent for Android apps. You give it an .apk; it decompiles the app, investigates it for security issues the way a human analyst would — planning, running real static-analysis tools, and reasoning about what it finds — and returns a prioritized, structured report.

It is deliberately not a pattern-matching scanner. It is an agent: it decides what to look at next, pulls apart native libraries, verifies its own hypotheses with quoted evidence, and cites the security standard each finding maps to rather than relying on the model's memory.

2. How a scan works

Every scan runs the same first stage — extraction — then hands the facts to the AI:

        your APK
          │  decompile (jadx + apktool) · parse the manifest · extract native strings
          ▼
    extracted facts ──►  Claude (analysis)
                           │   agentic mode also uses tools:
                           │   list_dir · read_file · grep · strings_in_lib · search_knowledge
                           │   findings grounded by ── RAG knowledge base (OWASP MASVS + methodology)
                           ▼
                    structured JSON findings ──►  prioritized report (view in browser · download PDF)

In agentic mode the model runs a tool-driven loop: given a small seed view of the app plus a toolbox, it decides what to read, grep, or disassemble next. When it has investigated thoroughly it stops, and a final structured pass emits the report against a strict schema — severity · OWASP Mobile category · CWE · location · evidence · exploit path · fix · cited standards.

All analysis runs in the local process; the browser only uploads the APK, shows live progress, and renders the finished report.

Agentic mode consistently finds more real issues because it verifies rather than guesses — in our case study it caught the same headline issues as single-call plus three extra code-level bugs, and retracted a false positive single-call had asserted.

Costs are rough estimates that vary with app size, and are billed to whichever API key runs the scan (yours if you provide one).

Without a Voyage key an agentic scan still runs fully — it explores the app with tools and reports — but the knowledge base is not consulted at all (no MASVS/methodology retrieval and no citations); the agent falls back on its own knowledge plus the methodology built into its prompt. Single-call mode never uses the knowledge base either. So the practical difference between single-call and an ungrounded agentic scan is the agentic loop's tool exploration (reading files, grep, disassembling native libs) — not the knowledge base.

4. Why it needs API keys

APKAnalyst doesn't run its own AI model — it calls hosted APIs. Two keys are involved:

Anthropic API key required

This powers the analysis itself: the reasoning, the tool-use loop, and the final structured report are all Claude calls. No Anthropic key (in the form or in .env) means no scan. Get an Anthropic key ↗

Voyage API key optional · agentic only

This powers RAG grounding. In agentic mode the agent's search_knowledge tool turns its query into an embedding (a numeric vector) using Voyage AI, then finds the most relevant OWASP MASVS controls, MASWE weaknesses, and MASTG tests by meaning. Those become the citations attached to each finding.

  • Single-call mode never uses Voyage.
  • Agentic mode still runs without a Voyage key, but ungrounded — the retrieval step quietly no-ops, so findings carry fewer/weaker standard citations. Because of that, an agentic scan warns you before any paid call when grounding can't run (missing key or missing index), so you can continue ungrounded or cancel.

5. The Voyage key: free vs paid

Voyage's embedding usage is generous, but the throttle depends on whether the account has a payment method:

AccountRate limitWhat you feel
Free tier, no card 3 requests/min · 10K tokens/min Each search_knowledge call may wait ~a minute, so an agentic scan feels slow (long silent gaps in the console).
Free tier, payment method added Throttle removed Retrieval is near-instant. You still get Voyage's large free token allowance — the whole corpus plus a scan's queries is tiny.
The throttle is a Voyage account setting, not something the tool controls. Adding a payment method to whichever Voyage account's key is used is what removes it. Supplying your own Voyage key here only speeds things up if your account is card-backed; a card-less free key hits the same 3 req/min limit as any other.

6. How your keys are handled

You run APKAnalyst yourself, so "the server" here is your own local process — not a remote service.

Where a key goes

  • A key you paste in the browser is sent to the local process running on your machine.
  • It is used only to build that one scan's API client, held in memory (RAM) for the duration of the scan.
  • It is never written to disk, never logged, and never stored in the job record the status/report endpoints expose.
  • When the scan finishes (or is cancelled) the request ends and the key is discarded.
  • The only place your key leaves your machine is the calls to Anthropic (and, for grounding, Voyage) that actually run the analysis.

Where the keys come from

For each key APKAnalyst uses the value you type in the form, or — if you leave the field blank — the one in your .env file. An Anthropic key must be available from one of those two places for a scan to start; a Voyage key is optional (it enables grounded citations). Nothing is shared between users because there are no other users — it's your machine.

Note. Keys in .env are read once at startup. After adding or changing a key there, restart the process (Ctrl+C and relaunch) — a running process won't pick up the change. A key typed in the browser takes effect immediately.

7. Protecting yourself (recommended)

Good habits for any API key you use with a tool like this — they limit what a mistake or a leak could cost you:

  • Create a dedicated key just for this, separate from any production key.
  • Cap its spend / rate limit where the provider allows (Anthropic and Voyage both let you set per-key limits), so an unexpected loop or leak can't run up a large bill.
  • Revoke it when you're done. A one-off scan doesn't need a long-lived key — delete it afterward from the Anthropic / Voyage dashboard.
  • Never reuse a key that has broad access to other projects or billing.

8. Your APK & your data

  • Uploads are capped (200 MB by default) and must be .apk files.
  • Each scan gets its own temporary workspace for the decompiled output; it's deleted after the scan.
  • Job state (progress + the finished report) is kept in memory only — it isn't written to a database and doesn't survive a server restart.
  • The live console shows only static stage text, the uploaded file's name, and the target app's own decompiled paths/queries — never your keys or server internals.
  • Your APK is sent to Anthropic (and, for grounding, your query text to Voyage) as part of the analysis. Don't upload an app you're not entitled to analyze, or one containing secrets you can't share with those providers.

9. Grounding & citations

Findings are grounded in a local vector knowledge base with two roles:

  • Rulebook — OWASP MASVS. The Mobile App Security Verification Standard controls, so a finding cites which standard it violates.
  • Playbook — OWASP MASWE + MASTG. The Mobile Application Security Weakness Enumeration (concrete weaknesses) and the MASTG Android test procedures, which guide how to find and confirm an issue. All fetched from public OWASP repos; you can optionally add your own local notes to supplement it.

The corpus is embedded once with Voyage AI into a small local vector store; at analysis time the agent retrieves the most relevant controls/notes by meaning and records them on each finding. As a guard against the model inventing a citation, any cited standard that isn't actually in the corpus is dropped before the report is shown — so every citation you see is a real, resolvable reference.

10. Running it yourself

APKAnalyst is open to run locally. It needs jadx, apktool, and strings on your PATH, plus Python dependencies.

pip install -r requirements.txt
cp .env.example .env          # add ANTHROPIC_API_KEY (and VOYAGE_API_KEY for grounding)
python3 run.py --build-kb     # build the RAG index once
python3 -m uvicorn webapp.server:app --port 8077

Then open http://127.0.0.1:8077. --build-kb fetches the OWASP knowledge (MASVS + MASWE + MASTG) from their public repos, so grounding works out of the box. You can optionally add your own local notes to supplement the playbook — see the project README and playbook/README.md.

12. Privacy & data

  • Everything runs on your machine. APKAnalyst has no backend service collecting your data — the process runs locally and keeps nothing beyond what's noted below.
  • Your APK is processed transiently. It's unpacked into a per-scan working directory that is deleted right after the scan. The app isn't archived or stored long-term.
  • Where your data goes. To analyze the app, its extracted contents are sent to Anthropic (the analysis model) and, for grounding, query text to Voyage AI (embeddings). Their processing is governed by their own terms and privacy policies. Anthropic does not train its models on data submitted through its API by default.
  • API keys. A key you paste is used only for that scan and never stored, logged, or written to disk (see §6).
  • Reports. A finished report is held in memory only and is not written to a database; it does not survive a restart.
  • Don't scan sensitive or unauthorized apps. Only analyze apps you're allowed to and that you're comfortable sending to the third-party providers above.
